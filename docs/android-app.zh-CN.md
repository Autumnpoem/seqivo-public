# Android 应用接入与安装

**公开安装入口：**下载普通签名 release APK（应用 0.4.1 / versionCode 15），按[手机安装与连接指南](mobile-install.zh-CN.md)操作。它不含测试 CA 或预设服务器；新发布签名不能覆盖旧 debug 测试包。发布检查见[验证记录](android-public-release-results.json)。

## 自行构建签名发布包（macOS / Linux）

准备 Node.js 24、Python 3、JDK 17、Gradle 8.9、Android SDK Platform 35 和 Build Tools 35.0.0。在仓库根目录设置 `JAVA_HOME`、`ANDROID_SDK_ROOT` 和 `SEQIVO_ANDROID_GRADLE`（Gradle 可执行文件的绝对路径），然后执行：

```sh
node scripts/release-android.mjs init-key
node scripts/release-android.mjs build
```

`init-key` 仅供第一次创建你自己的发布密钥，已有密钥时会停止，避免覆盖；后续只运行 `build`。默认密钥和密码文件存于本机 `~/.local/share/seqivo-release-signing/android/`，与仓库分开，请自行安全备份，不要提交或分享。也可用 `SEQIVO_ANDROID_SIGNING_KEYSTORE` 和 `SEQIVO_ANDROID_SIGNING_PASSFILE` 指向已有材料；别名需为 `seqivo`，密码文件仅本人可读，密码至少 24 字符。自签名包不能覆盖作者或其他人签名的安装。

脚本会测试、检查、生成版本 0.4.1 / code 15 的 APK，输出到 `.runtime/mobile1113/Seqivo-0.4.1-android.apk`；已有同名产物时会停止，请先核对并归档上一次结果。它不会安装到手机。后续版本需明确更新脚本中的版本号、应用版本及验证记录。原 `pnpm android:build` 仍是调试包构建流程，不能代替此发布步骤。

## 本地构建与安装

需要 Node.js、JDK 17、Android SDK Platform 35、Build Tools 35.0.0、Gradle 8.9，以及本机**已有**的 Android Debug 密钥（通常是 `~/.android/debug.keystore`）。脚本在密钥不存在时失败，不创建或改写签名密钥。设置 `JAVA_HOME`、`ANDROID_SDK_ROOT`，确保 Gradle 在 `PATH` 中，或用 `--gradle` 指向现有 Gradle 程序。以下命令在仓库根目录执行；每次都显式填写正整数 `versionCode`：

```sh
JAVA_HOME=/path/to/jdk17 ANDROID_SDK_ROOT=/path/to/android-sdk \
  pnpm android:build --version-code 1 --gradle /path/to/gradle-8.9/bin/gradle
```

也可以直接执行 `node scripts/build-android.mjs`，参数相同。当前仓库不包含 Gradle wrapper，需按上述版本准备外部 Gradle。

脚本运行普通 debug 单元测试，构建 debug 和 release，并核对包名、版本号、debug 签名、默认服务器地址为空，以及两个普通 APK 均不含测试 CA 或测试网络配置。成功后把**仅供本地验证**的 debug APK 放在忽略版本控制的 `.runtime/android/deliverables/seqivo-debug-v<版本号>.apk`，构建日志在同目录。脚本不下载工具、不创建密钥、不修改全局配置；Gradle 只按项目仓库配置解析声明的依赖。如果环境需要镜像，可自行设置 `SEQIVO_ANDROID_GOOGLE_MIRROR`、`SEQIVO_ANDROID_MAVEN_MIRROR`；脚本不内置镜像地址。

此普通 debug APK 使用本机 Android Debug 签名，可以在**你自己授权的测试设备**上通过 Android 系统安装界面安装，或用 `adb install`。本脚本不会连接或操作设备。`release` 构建产物目前是**未签名**的 `android/app/build/outputs/apk/release/app-release-unsigned.apk`，不能作为可安装的正式版分发；正式交付需要专有签名密钥、发布流程和真机验收。

`fixtureDebug` 是独立包名的隔离测试变体，只有在显式提供 `SEQIVO_ANDROID_TEST_CA` 后才可构建。它仅用于本机隔离 HTTPS Hub 和模拟器，不会进入 `.runtime/android/deliverables/`。普通交付脚本会从其 Gradle 子进程移除该变量，同时移除 `SEQIVO_ANDROID_DEFAULT_ORIGIN`，因此交付 APK 首次打开需要手动填写地址。不要把私有 Hub 地址、账号、证书或令牌放进源码和文档。

## 原位升级

升级同一普通 debug 应用时，把 `--version-code` 提高，使用**相同包名和相同 Android Debug 签名密钥**构建，然后在已授权的设备上安装新版。`adb install -r /path/to/seqivo-debug-v2.apk` 是一种可选安装方式；它通常保留应用私有的服务器地址与 Cookie，升级后仍需实际核对登录和任务数据。更换签名密钥或从独立的 `fixtureDebug` 包切换到普通包不属于原位升级。正式版签名及数据迁移尚未验证。

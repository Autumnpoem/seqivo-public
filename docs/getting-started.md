# 使用序程 · Seqivo 0.2.3

第一次在新电脑接入项目，先看[图文上手指南](new-computer-guide.zh-CN.md)，在当前源码的“项目接入”页面复制提示词交给当前对话；旧版可使用[AI 进度汇报说明](seqivo-progress-prompt.zh-CN.md)。基础接入读取本地项目的进度事件，不要求业务 API 或业务数据库。

打开桌面应用，选择包含 `.taskboard/project.json` 的目录导入项目，或新建项目并填写目标与本机目录。再把工作拆成任务：写清期望结果、一个使用例子、当前进展、实现思路和逐条验收标准。任务详情中的证据、来源会话与内容版本可以展开查看。外观可选浅色、深色或跟随系统；桌面端还能打开独立悬浮窗。关闭主窗口会隐藏到托盘，选择托盘中的“退出并停止后台”才会退出服务。构建、数据目录和桌面运行条件见[桌面构建说明](desktop-build.md)。

## 会话、执行与人工验收

创建任务时可以填写“来源会话”：它记录这项工作从哪里来，任务清单的“会话范围”可以按全部、未绑定或指定会话筛选。来源会话**不**授予控制权。“执行会话”才是看板继续或暂停任务所用的绑定；手机端只显示是否已绑定，不显示会话 ID。

要用 Codex 执行，先绑定与会话工作目录一致的项目绝对路径。在任务详情选择“新建 Codex 会话”可创建并绑定一个新会话，**创建本身不发送任务**；也可以在“编辑任务”中绑定已有会话 ID。若创建返回未知或等待授权，先去 Codex 核查，勿再次创建。然后在“接入与插件”填写本机 Python 3 与 Codex CLI 路径，保存、检查连接并启用插件。插件在本机启动 `codex app-server`，沿用现有登录与模型配置；只对你信任的本地插件和路径启用。插件总开关与每项任务的自动继续策略分开，策略默认关闭。只有明确启用的任务才会在额度条件满足时尝试继续；人工暂停优先。

“继续任务”的请求发出后，只有执行工具确认开始才显示已开始。额度等待、发送中、审批中、未知与失败各有独立提示。暂停只针对看板发出的匹配执行轮次。遇到审批或未知结果，不要重复发送；先处理执行工具中的授权，再用“核实会话状态”查询实际状态。核实后自动继续仍保持关闭，需要你再次启用。Codex 已通过隔离任务执行、协作和手机网页发起的真实两轮代码修改；完整五小时额度恢复周期仍待实测。Claude Code 和 Cursor Agent 有插件入口，但依用户当前选择，尚未做真实执行验收。

“提交结果”表示工作已交付待检查，并不等于完成。请打开证据和验收标准，由人选择“通过”或“未通过”并写说明。当前版本证据齐全、没有未解决偏差且人工通过后，任务才计入已完成。未通过的原因出现在“交付偏差”；解决后重新提交、补充证据并再次验收。目标或实现要求变更会使旧验收失效。

## 测试验证与重新验证

详情会先列出“验证待办”：明确哪些还没验证、哪些尚未实现、哪些需要确认。点开一项即可看到具体步骤、通过标准和当前缺少的条件；首项默认展开。待办计划不会自动变成测试通过。旧记录缺少步骤时会提示补充，旧版本计划不会覆盖当前要求。当前项目的具体待办与维护规则见[验证待办说明](verification-backlog.md)。

点击待办旁的圆圈可标为“已办结”，再次点击恢复“未验证”；填充状态和办结数量会保存。点标题展开详情，勾选不会误关详情。子待办的人工标记不会改变整项任务的测试结论或验收结果。

测试状态与人工验收分别保存。清单可筛选“已验证”“部分验证”“验证未通过”“需重新验证”和“待验证”；详情显示本次覆盖的标准、说明和证据引用。整项验证通过要求结果已提交、没有未解决偏差，并覆盖当前全部验收标准。记录入口使用本地 owner 权限；AI 的文件/MCP 汇报不能自行把任务标为已验证。

更改内容、标准或关键执行条件后，之前的验证可能失效，需要重新验证。人工验收未通过时，也不会继续把原先的测试通过显示为当前有效。测试通过并不代替人工验收；人工验收通过也不会凭空生成一份测试记录。

## 协作计划

桌面端“协作计划”从已有、未完成且绑定执行会话的任务中选择成员，设置执行、审查等角色、请求模型、依赖关系与预算。先“保存草稿”，核对后再按“明确启动”；创建草稿不会运行 AI。独立审查要用单独任务和独立绑定的会话；审查任务可针对已提交且执行轮次确认结束的任务，但最终通过仍由人验收。普通依赖则要等所依赖任务当前版本通过人工验收。

看板只把执行工具返回的模型写作“实际模型”；没有可靠元数据时显示“未确认”，填写的“请求模型”不是运行证明。未知状态用“核对执行状态”查询工具，结果仍未知时保持锁定，不会自动重试。计划按项目目录串行控制同一工作区的执行，且受同时启动数、总启动次数和时间预算限制。它不会自动创建 Git worktree 或替你选择模型与全局设置。细节见[协作计划协议](workflow-api.md)。

## 历史、备份和项目交接

“项目交接”提供可以复制到新对话的目标、进度和下一步摘要。“记录备份”能按项目或任务查看历史、下载带校验的备份，以及在明确输入“恢复”后替换当前记录。单文件上限为 **16 MB 或 100,000 条记录**。修复记录中的“重建记录”只从本地历史重建索引，不运行任务；恢复或重建前，都要断开远程同步、关闭自动执行插件并核实未结束的执行。

恢复备份不会自动运行旧任务；它会清空项目目录与执行会话绑定、不恢复旧执行租约，并使旧的通过验收失效。原协作计划标为已恢复，需要重建。恢复后先核查可能仍在外部工具运行的会话，再重新绑定目录和会话、重新验收，按需重新启用策略。恢复不能证明外部 AI 已停止。历史和备份只保存看板记录，不是完整聊天记录。

## AI 通过文件或 MCP 汇报

文件和 MCP 都使用同一个数据库，不需要复制聊天全文。为项目选择本地目录后，服务生成 `.taskboard/tasks.json` 和 `CONTEXT.md`。让新对话先读 `CONTEXT.md`，再按原始要求继续；不要让 AI 直接改写数据库或生成的快照。

AI 可以把独立事件写入 `.taskboard/inbox/<任意唯一名>.json`：先写临时文件，再重命名为 `.json`。从 `tasks.json` 读取真实任务 ID 和 revision。例如：

```json
{
  "eventId": "unique-event-id",
  "type": "task.update",
  "taskId": "任务的真实 UUID",
  "expectedRevision": 3,
  "payload": {
    "summary": "已写好按扩展名统计文件的函数，正在检查无扩展名文件。",
    "approach": "读取传入的文件名列表并分组计数，不移动原文件。",
    "status": "running",
    "nextStep": "运行统计用例并保存测试记录。"
  }
}
```

服务通常约一秒内处理，回执写入 `.taskboard/receipts/`。支持 `task.create`、`task.update` 和 `evidence.add`。重复事件 ID 不会重复执行，也不能用同一 ID 提交不同内容；修订冲突要重新读取并合并。AI 汇报不能改写既定目标、验收条件、会话绑定或人工暂停。

MCP 通过 stdio 提供 `project_context`、`task_list`、`task_create`、`task_report`、`task_evidence`、`task_decision`。在支持 MCP 的工具中添加服务器配置，路径按本机修改：

```json
{
  "mcpServers": {
    "tuijin": {
      "command": "/absolute/path/to/node",
      "args": ["/absolute/path/to/project/server/mcp.mjs"],
      "env": {"TUIJIN_DATA_DIR": "/absolute/path/to/tuijin-data"}
    }
  }
}
```

Node.js 需 24 或更新版本。桌面端将服务地址写入数据目录的 `connection.json`；MCP 使用 `access.json` 中的 reporter 密钥，只能读取背景、新增任务、汇报和附加证据，不能验收或启动执行。上述模板不会自动修改任何 AI 工具的配置。

## 手机连接与自托管 Hub

手机访问自托管 Hub 的 HTTPS 网页，查看项目电脑主动同步的**已授权项目**；模型仍在项目电脑上运行。新用户可公开注册，得到独立空间，再用同一账号在电脑和手机登录。已有 Hub owner 应先用原访问令牌进入已有空间，在“账号”中选择“为当前空间设置账号”，保留原项目和任务；直接注册会得到另一个空空间。项目电脑在“手机连接”填写 Hub 地址、账号密码并勾选要同步的项目。部署与 TLS、数据备份步骤见[Hub 部署指南](deployment.md)；详细步骤和隐私边界见[账号与远程对话](accounts-and-conversations.md)。

管理员仍可生成限定项目、权限和有效期的一次性配对码，供项目电脑或手机连接；仅查看者不能提交命令。已登录账号的手机可在“与 Codex 对话”中向所选项目发送自然语言消息并查看可见 AI 与工具输出，也可继续已有对话；这不是手机上的系统 shell。Hub 保存有限的任务快照、命令回执，以及被请求查看的最多 5 项任务的有限可见对话内容，不保存本机目录、隐藏推理或执行会话 ID。可见输出可能包含代码和秘密，HTTPS 不提供端到端加密。电脑须保持运行和联网，旧桌面版需升级；网页约每 2 秒更新一次。电脑离线或回执未知时先核查，不要重复发送。改密码会撤销浏览器会话，但已配对设备仍需单独撤销；令牌不要放进网址或公开文件。

本次账号、远程会话的 167 项单元及集成测试、Chromium/WebKit 手机视口流程、真实 Codex 两轮文件修改与回传均通过；公网账号、隔离和原有桌面数据保留也已核对。实体手机、Windows/Ubuntu 原生运行仍需实机验收。详见[本轮验证结果](accounts-conversations-validation.md)。

同一数据目录只运行一个本地服务。备份运行中的 Hub 和恢复方法以[部署指南](deployment.md)为准；不要把桌面看板备份误当成 Hub 凭据备份。

新版默认打开[需要我处理收件箱](inbox-and-delivery-plan.md)，任务清单仍可从导航进入。

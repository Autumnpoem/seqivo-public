# 待处理收件箱与交付闭环

本轮从 v0.3.0、提交 `b256038` 增量实施。首页聚焦四件事：需要决定、等待验收、任务阻塞、结果未知。原有任务、证据、偏差、账号、远程对话和目录执行锁继续使用。

## 收件箱怎么用

每张卡片先显示通俗的当前进展、还需处理的事项和下一步。完整说明、可能影响与**任务内容版本**可展开查看，并可回到关联任务。进展摘要不等于已验证；任务内容版本也不等于 Git 提交或运行中的构建版本。

| 类型 | 可采取的操作 | 操作后的含义 |
| --- | --- | --- |
| 待决策 | 选择带取舍说明的选项，或填写答复 | 保存人工决定，供新对话读取；不会自动启动 AI |
| 待验收 | 打开任务证据，进入现有人工验收流程 | 仍须当版证据和原始验收条件；处理提醒不代表验收通过 |
| 阻塞 | 查看缺少条件，补充信息或进入关联任务 | 补充信息不会伪造阻塞已消失 |
| 结果未知 | 点击「核实这次操作」，检查原操作记录；也可查看关联任务 | 区分已执行、明确未执行和仍未知，不重发原指令 |

“稍后处理”只移动提醒，不完成任务。历史记录保留原事项及状态；新版本可能产生新的验收事项。双端提交使用操作 ID、任务修订号和事项修订号，旧页面必须刷新后重新确认。手机掉线时可读缓存，不能离线排队处理收件事项；提交结果不明时保留原操作记录。

手机自身断网或无法连接服务时，可继续查看已加载的内容，不能提交新的决定、修改或验收。恢复网络信号后，须成功同步当前状态才能恢复操作。这与“目标电脑离线”不同：后者仍沿用既有任务操作的显式排队选项；收件事项和新对话不自动离线排队。

手机只看已授权项目。未明确共享的决策、验证条件及本地阻塞详情留在电脑上，手机会提示需要在桌面核对。账号和设备权限保持原规则。没有安装手机 App 也可使用现有 HTTPS 网页。

原操作核实入口现可查询电脑保存的明确回执或执行前标记，按证据恢复后续操作。电脑崩溃且没有留下充分记录、原节点失联或授权已撤销时，仍保留未知与限制；不能靠清除提示绕过。操作说明和边界见[远程操作核实](remote-operation-recovery.md)。上述断网保护针对任务、收件箱和远程执行入口，账号及配对管理是独立的权限流程。

## AI 如何发出明确决策请求

文件事件、MCP 和本地 API 使用同一领域逻辑，不从长聊天中猜测决策。MCP 新增 `task_decision`；只允许请求，不能替人答复或验收。`requestId` 重试时保持不变；内容变化应创建新请求并携带当前修订号。

```json
{
  "taskId": "TASK_ID",
  "expectedRevision": 3,
  "requestId": "storage-choice-v1",
  "title": "确认数据保存方式",
  "summary": "页面已有基本交互，持久保存需要确定方案。",
  "impact": "确认前无法验证重启后数据仍存在。",
  "shareWithRemote": true,
  "options": [
    {"id": "sqlite", "label": "本地数据库", "consequence": "单台电脑使用，数据保存在本机。"},
    {"id": "service", "label": "现有服务接口", "consequence": "可多设备共享，需要配置服务。"}
  ]
}
```

本地 `POST /api/tasks/:taskId/decisions` 使用上述对象去掉 `taskId`。文件事件为 `type: "decision.request"`，顶层放 `eventId`、`taskId`、`expectedRevision`，其余字段放 `payload`。`.taskboard/CONTEXT.md` 与 `project_context` 展示人工决定和未答复请求，让后续对话遵循现场信息。

## 手机实测操作单

测试必须使用独立的可丢弃项目，避免改动正在开发的代码。手机使用已有空间的账号登录，不重新注册一个空空间。测试期间电脑保持序程运行、连接成功；从手机新建/继续的 Codex 使用电脑上的权限，账号只给可信操作者。

记录 iOS/Android 版本、浏览器版本、电脑版本、开始时间和网络。iPhone Safari 与 Android Chrome 各跑一次；其中一条走 Wi-Fi，另一条关闭 Wi-Fi 走蜂窝网络。

1. 登录已有空间，确认原项目、旧任务与验收记录仍可见；退出后不能查看数据，再登录回到原空间。
2. 选测试项目，新建对话让 Codex 修改一个明确的小文件；看到任务状态和输出，确认电脑上文件实际改变。发送第二条消息继续修改，核对同一对话以及没有重复任务。
3. 在测试运行期间点暂停。记录请求状态与实际执行器结果；结果不明时保持未知，不再次发送相同任务。暂停响应不证明所有 OS 子进程已停止，也不开放终端接管。
4. 首页选择一个待决策事项，阅读发生/影响/取舍后答复；电脑确认只保存一次。另一端的旧页面再次提交应提示刷新，不能覆盖先前决定。
5. 打开待验收事项，查看原始要求、当版证据与具体待验证步骤。验收/退回修改后返回首页，核对状态及历史；没有证据不能通过。
6. 手机切飞行模式：仍可辨认离线快照，写操作禁用。恢复网络、锁屏再解锁、刷新网页：原事项与提交回执仍正确，不自动重发。
7. 切换日夜主题和系统大字号；窄屏没有横向溢出，按钮可点击。用一分钟找到当前最需要处理的事项，并反馈是否还必须翻完整聊天。

每步记录“通过 / 失败 / 未验证”，失败记录时间、动作和现象。浏览器手机视口通过不能替代此清单。实际用量可能消耗 Codex 限额，但无需向任何人发送密码、令牌或私钥。

## 升级与回滚

先关闭桌面应用并确认后台服务正常退出，再备份完整应用数据目录及安装包；运行中的 SQLite 需使用 SQLite online backup，不能只复制可能遗漏 WAL 的主文件。Hub 用现有备份服务保存数据库和部署目录，防火墙及 HTTPS 配置不变。

新版本只增补收件箱 metadata、人工决策和已知验收历史，旧版验收字段和版本不会被重新判定。旧程序覆盖过的更早验收没有可恢复证据，不能补造。

副本演练命令（源数据库只读，临时数据自动清理）：

```sh
node scripts/verify-inbox-upgrade.mjs /path/to/board.sqlite /path/to/report.json
```

回滚时先停新程序，保存升级后数据以便追踪，再将**整个升级前数据库备份及相应连接文件**和旧安装包恢复。新版本使用期间新增的决定应先导出保存，回滚会回到备份时刻。勿将用户数据删除后重新初始化。可移植归档导入为了防止误执行，会清除目录/会话绑定并使旧验收待重验，不能当作保持原状态的精确回滚。

# Linux 异常重启恢复：独立任务管理进程

最新 LINUX1086 已接入 Core／插件宿主，异常恢复检查通过；正常启动仍存在待核实的进程快照失败，未打包或部署。见[当前接入状态](linux-executor-recovery.md)。下文保留 LINUX1085 当时的独立组件结果。

LINUX1085 已完成独立后台组件，并在 Ubuntu 22.04 普通账户下通过 6 项真实进程检查。**尚未接入正式任务流程、安装包或线上服务。**它解决控制进程消失后，如何继续核对和停止原任务；不代表 AI 已完成任务，也不自动允许人工接管。

`server/linux-executor-job.mjs` 和 `plugins/codex-autocontinue/linux_executor_job.py` 在任务启动前建立私有记录及管理进程。管理进程先成为子进程收养者，再启动任务；调用方退出后仍可核对原任务及后代。新调用方只恢复原记录，不再次启动任务或补发输入。记录目录和文件分别限当前用户访问；本地连接使用独立能力令牌。停止只针对已核对的原进程，并通过 pidfd 发送信号；只有后代已收割完毕才记录停止完成。管理进程无响应时，连接和回执合计 5 秒超时，返回结果不明。

本轮通过：

- 调用方退出后恢复原任务并停止，启动次数仍为一次。
- 原任务快速退出后，恢复记录并收养、停止两次派生的后代；不把已退出的原进程报告为启动成功。
- 核对由非主线程派生的子进程。
- 拒绝任务、项目或目录不符的恢复请求，原任务保持运行。
- 父进程未收割已退出子进程时，仍能停止并收割原任务。
- 管理进程被暂停时及时报告结果不明；恢复后按原任务清理。

最终 6 项通过、0 失败、0 跳过；测试结束无遗留子进程，外层测试清理器未发送信号，临时目录已移除。初次及修前失败保留在[结果记录](linux-executor-job-test-results.json)：快速退出场景先修正测试契约，随后复现并修复退出子进程导致管理进程退出、请求没有超时两处问题。测试使用受控进程，没有调用真实 AI。

下一步将该组件接入 Core 与插件宿主，绑定原任务、工作目录、工作树、交还代次和执行租约。在隔离环境模拟 Core 异常退出后，须核对原任务确已停止、工作区无其他写入者、原终端现场仍一致，才能恢复人工输入；旧 AI 回合的业务结果仍保留为未知。没有该管理进程的历史记录不能被升级成停止证明。真实 AI、完整应用异常重启、Ubuntu 桌面安装及 Windows 原生验证仍是待办。

原受管终端恢复和同一 Core 内的交还结果分别见[终端接入](linux-core-integration.md)与[执行器接入](linux-executor-integration.md)。Ubuntu 依赖配置见[打包说明](ubuntu-packaging.md)。

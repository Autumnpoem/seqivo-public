# Linux 原任务恢复与当前待办

LINUX1086 已把独立任务管理进程接入 Core 和自动继续插件。控制程序异常退出后，新进程只恢复原任务，不重发旧命令；确认相关进程停止后，仍将未确认的业务结果保留为“未知”。人工接管继续检查当前工作目录和原终端。

LINUX1088 最新组合检查为 **4/4 通过**：运行中的任务异常恢复、已中断但缺少停止证明的任务恢复、缺少回合编号时拒绝接管，以及同一控制程序暂停 AI 后交还原终端。使用真实 Linux 进程、tmux 和可控测试协议，没有调用真实 AI；无跳过、遗留测试进程或外层强制清理。中间版本的 Core／权限／租约组合 14/14、原生组件 7/7、Mac 相关 4/4 是历史范围，不合并计数。

**重复检查导致的启动误判已修复。** 先前创建会话时遇到 `list_changed_during_scan`，是 Host 在 Core 核验前进行冗余全量进程扫描所致。现仅跳过原 Linux job 的这次扫描，仍由 Core 检查私有任务记录、实时进程身份链与受管现场；旧执行入口、启动前基线和暂停时的检查保留。确定性回归在旧代码失败，修复后 1/1 通过。

**LINUX1089 已补上发送前拒绝的收尾。** 同一控制进程创建新会话，在 Core 准入或重验时被拒绝后，会停止本次原任务进程，保留“未启动”，同一请求不重发；用户以新请求明确重试时才创建会话。专用收据只证明本次原进程退出，不解除租约、不授予人工接管，也不补造准入记录。退休回调首次失败时保留记录，同一实例正常关闭时可以重新核对。

本轮 Host 5/5、真实 Core 2/2、受影响的异常恢复与原终端交还 4/4 通过，无跳过、遗留进程或外层强制清理。真实 Core 还验证了会话结果未知、原进程身份变化时拒绝收据且不改授权记录。**更早的连接／初始化失败、替换控制进程后的收尾、真实 AI 与原生安装仍待验证。** 当前代码在目录变化、最终保存失败时保留限制，但本轮未注入这两种故障；不能宣称所有启动失败均已解决。详见[发送前收尾结果](linux-session-abort-test-results.json)。

本次修复了长应用目录下的本地连接、恢复后暂停入口、人工接管后复核原停止收据，以及正常暂停被误留为“结果不明”的状态冲突。测试清理改为等待原终端会话退出，不再重复关闭它。进程快照不完整时仍拒绝放权，未放宽安全检查。

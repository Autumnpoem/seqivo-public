# 本机终端插件：使用与开发契约

本机终端以随应用打包的内置插件 `local-terminal` 提供，manifest 声明 `terminal.local.v1`。插件由 Core 拥有，使用 Core 内的终端管理器和授权流程；它不通过通用 worker 执行命令。已有 Core/PTY/tmux 集成及界面模拟测试；新增的停用中断恢复范围见[测试记录](terminal-plugin-test-results.json)，历史回归结果保持原有范围。这不代表最终 App、原生界面或跨平台交付已验收。

## 用户操作

仅本机 owner 可在插件页面打开“本机终端”，查看状态、检查、启用或停用入口；其他角色不能管理它。启用或停用后应刷新并确认 Core 返回的实际状态；遇到“状态待核实”时先检查，不要重复启停。

停用只关闭 Seqivo 提供的终端入口及其自身终端附着，不会删除用户的 tmux server、会话或其中程序。活跃的普通 Shell 仍由进程占用时，停用会被拒绝；先正常结束该 Shell 再重试。停用是插件入口管理，不会把任务控制权交还 AI，也不会解除 `human` 或 `unknown` 状态的保护。

停用和启用都先持久化切换意图。若停用结果在同一 Core 进程内未能确认，可使用页面“检查”重试核验原有句柄。如果停用过程中应用中断，重开后可点击“检查”：停用前已可靠记录“没有终端附着”时，可核对记录完成停用。macOS 上，若停用前已完整记录原有 tmux 连接的进程身份，也可在确认这些原连接确实退出后完成停用；tmux 会话和其中的程序继续保留。之后仍需单独点击“启用”。旧记录、记录损坏或曾有无法确认的终端进程时，会继续显示待核实，不会自动开放输入。不要删除状态记录、锁或会话元数据来绕过保护。

## 开发契约

- manifest 固定标识为 `local-terminal`，API 版本为 `1`，契约与能力为 `terminal.local.v1`；这是随应用提供的可信内置插件，不是第三方插件市场或 OS 沙箱。
- Core 是 PTY 授权与执行协调的权威。终端 manager 在创建连接、会话和输入等受保护路径检查插件生命周期状态；插件页面不能自行授予终端权限。
- 生命周期状态为启用、停用、停用中或结果未知。停用前先检查活动 Shell 安全性，再持久化停用意图、冻结入口并处理本插件的附着。状态写入失败或关闭结果不明时保持输入冻结，不能把未知显示成成功。
- 仅在确认停用后才可重新启用；启用前先核对恢复现场。Core 正常关闭也必须确认没有未决的停用结果。
- 程序升级应遵循：停用入口并正常退出 → 使用兼容同一契约的程序升级 → 检查现场 → 再启用。此流程尚无最终安装包验收；当前没有热升级保证，也没有第三方插件隔离机制。

## 尚未完成的边界

已验证的本机 Core/PTY/tmux 场景中，停用再启用及关闭 Core 后，原 A/B pane 的 PID 与 `/bin/ps lstart` 秒级启动时间观察保持不变；这不是精确进程出生身份核验。另一项干净停用重启测试只验证插件仍停用且 profile 保留，没有活动 pane。活动普通 Shell 会阻止停用。新增恢复覆盖完整空附着记录，以及 macOS 上完整记录的原 tmux 连接。进程仍存活、记录不完整或原生核对不可用时必须保持保护；不会根据新的空连接列表推断旧进程已退出。插件页只做浏览器模拟，未验最终 App/原生窗口。此次新增代码已通过定向测试和独立审查，尚未打入现用安装包；带附着的恢复已有真实子进程和可写 tmux 测试，最终原生界面与手机连接中的在途切换组合仍待验证。平台覆盖、升级/回滚及最终 App 流程仍需分别验证。

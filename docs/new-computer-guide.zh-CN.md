# 在新电脑上用序程查看 AI 进度

适用范围：序程 v0.4.1，核对日期 2026 年 10 月 31 日。

你在电脑上用 Codex 或 Claude 写代码，序程读取项目中的任务记录，把“要做什么、做到哪里、还差什么”显示出来。最基础的接入只需要一个本地项目目录，不要求项目有网站、业务 API 或业务数据库。

本文先讲最短使用流程，再给出可以直接交给 AI 的说明。截图来自当前源码启动的隔离本地看板，使用专门创建的演示项目，不是你的正式项目，也不是新电脑原生安装验收。

## 1 先理解谁在做什么

```text
你给 Codex 或 Claude 布置任务
              ↓
AI 修改项目文件，并写入一条进度记录
              ↓
项目目录 / .taskboard / inbox / 唯一编号.json
              ↓
序程读取记录 → 写回执 → 更新任务、进度和证据
              ↓
你查看结果，决定是否验收

新对话 ← 读取 .taskboard/CONTEXT.md 和 tasks.json
```

序程内部有一个本地数据库，用来保存任务、历史和验收结果。这是应用自己管理的文件，你不需要安装、设计或维护业务数据库。项目里的 JSON 是 AI 与看板交换进度的入口，不是唯一的数据副本。

之前提到的“真实业务 API”，指的是另一项可选能力：如果 AI 正在开发网站，可以在运行预览里检查按钮是否真的调用了网站后台。它不属于基础接入条件。做脚本、桌面工具或纯本地项目，也能使用任务看板。

**自动发生的是文件被读取和界面更新。** AI 仍需按约定写进度；只在聊天里说“完成了”，看板不会凭空知道。当前也不会自动扫描所有 Codex／Claude 历史对话并还原任务。

## 2 在新电脑上启动序程

先安装并登录 Codex 或 Claude Code（二选一即可），具体命令和官方安装链接见 [README 的安装步骤](../README.md#ai-tools)。已经能正常使用时不必重装。再准备一个实际存在的项目文件夹，让 AI 和序程使用同一个文件夹。

### 当前安装情况

[v0.4.1 公开下载页](https://github.com/Autumnpoem/seqivo-public/releases/latest) 提供 Mac Apple Silicon 安装包，无需仓库邀请。源码及自有代码按非商业许可提供，允许个人非商业使用，禁止商用；第三方组件保留原许可。先确认“关于本机”显示 Apple M 系列芯片，再下载 ZIP，解压后把“序程.app”移到“应用程序”并打开。此包为本地临时签名，尚未经过 Apple Developer ID 签名和公证；首次打开时按 macOS 的“隐私与安全性”提示确认，不需要关闭系统安全功能。

Windows、Ubuntu 与 Intel Mac 本次没有新版安装包；可以按源码路线使用。安装 Codex／Claude 不会自动安装序程。

| 使用方式 | 需要准备什么 | 当前怎么使用 |
| --- | --- | --- |
| 已拿到匹配系统的序程桌面包 | 对应系统和处理器的安装包 | 安装后打开“序程”，按第 3 节绑定目录。打包版包含本地任务服务，无须单独配置业务数据库。 |
| 尚未拿到安装包 | Git、Node.js 24 或更新版本、pnpm 11 | 按下面的源码步骤启动本机网页界面，先完整使用文件接入。 |
| 自己构建桌面应用 | 上述环境，加 Rust 与对应系统的 Tauri 构建依赖 | 参见仓库的 `docs/desktop-build.md`。这属于开发者路径。 |

Mac、Windows、Ubuntu 都有构建配置，但原生安装与完整使用的验证程度不同。不要把“有配置”理解成“所有电脑都已经实测”。本教程实际演示环境是 Mac 上的本地网页界面。

### 现在可以复现的启动方法

在一个用于存放序程源码的目录中执行以下步骤。**序程源码目录与你要开发的项目目录可以是两个不同的文件夹。**

```sh
git clone https://github.com/Autumnpoem/seqivo-public.git
cd seqivo-public
pnpm install --frozen-lockfile
pnpm build
pnpm server
```

源码下载无需提供 GitHub 密码或令牌。请先在终端确认 `node --version` 为 24 或更新版本、`pnpm --version` 为 11；未安装时按 [Node.js](https://nodejs.org/en/download) 与 [pnpm](https://pnpm.io/installation) 官方说明安装。源码依赖中的终端模块可能需要本机编译工具，详见 [桌面构建说明](desktop-build.md)。

启动成功后，在这台电脑的浏览器打开 `http://127.0.0.1:4317`。终端应保持运行。打开序程源码目录中的 `.runtime/access.json`，把 `owner` 对应的值填入页面的“访问令牌”，点“进入看板”；不要把这个值放在网址中。此令牌用于本机网页入口，和 Codex／Claude 登录、手机账号是不同的东西。

如果你不想自己配开发环境，可把上面整段交给已安装的 AI，让它检查依赖并启动；应明确“仅监听本机，不更改现有模型、认证、服务器或插件配置”。拿到经过验证的桌面安装包后，日常使用不需要再执行这些源码步骤。

## 3 告诉序程项目在哪里

1. 打开序程，点击左上方的“新建”。
2. 选择 **AI 正在工作的那个项目文件夹**。桌面版点击“选择文件夹”；本机网页填写绝对路径。
3. 项目名称会根据文件夹自动填写，你可以修改；项目目标选填，不必先写一份计划。
4. 点“继续接入”，自动进入“项目接入”。同一目录已有项目时会打开原项目，保留任务和设置。
5. 已有项目也可在任务页点“接入 AI”，或打开“更多功能 → 项目接入”。保持序程后台服务运行。

![新建项目并绑定本地目录](assets/onboarding/create-project.png)

图中是隔离演示目录，请换成自己的目录。路径示例：Mac `/Users/你的用户名/Projects/file-helper`，Windows `C:\Projects\file-helper`，Ubuntu `/home/你的用户名/projects/file-helper`。不用照抄示例路径，所选文件夹应实际存在。

随后该目录会出现：

```text
你的项目/
├── 代码和其他项目文件
└── .taskboard/
    ├── REPORTING.md  序程生成的完整进度汇报说明
    ├── CONTEXT.md    给 AI 读的目标、任务和下一步
    ├── tasks.json    序程生成的任务快照和修订号
    ├── inbox/        AI 把新增任务、进展、证据写到这里
    └── receipts/     序程告诉 AI 这条记录是否已收下
```

Mac 和 Linux 默认可能隐藏以点开头的文件夹；可以让 AI 直接读取上面的路径，无须先在文件管理器显示它。

**普通代码项目第一次接入选“新建”。**“导入”只用于已经准备好 `.taskboard/project.json` 专用导入文件的项目。当前“新建”不会生成这个文件，也不能把 `tasks.json` 改名冒充它。旧电脑迁移完整记录应使用“记录备份”的导出与恢复流程。

## 4 让 AI 开始维护进度

在“项目接入”页面确认文件夹正确，等到“等待 AI 汇报”，点“复制提示词”，粘贴到正在使用这个项目的 Codex 或 Claude 对话中。提示词包含当前项目路径，并让 AI 读取 `.taskboard/REPORTING.md`、`.taskboard/CONTEXT.md` 和 `.taskboard/tasks.json`。

完整汇报说明会由序程自动生成到项目目录，无需再单独下载文件或自己编写 JSON。AI 按已确认的要求维护真实任务：开工、取得进展、遇到阻碍和结束本轮时，用通俗的话写清已完成内容、剩余内容和下一步，并检查回执。接入不会自动生成虚假的“检查成功”任务。

序程会更新未被修改过的生成说明。你编辑过的 `REPORTING.md` 会保留，页面可展开当前内容与新版说明进行比较；不会直接覆盖你的修改。任务快照仍会继续更新。

AI 在当前目录有文件读写权限时，就可以用这条路线。Codex 和 Claude 都可遵循同一套文件格式；这不意味着两者的专用执行插件都已通过真实环境验收。当前 Claude 的真实登录执行仍属于单独待验证范围。

希望同一项目的新对话沿用汇报约定时，展开“让新对话沿用汇报规则（可选）”，先查看将添加的内容，再点击“添加到 AGENTS.md”（Codex）或“添加到 CLAUDE.md”（Claude）。序程只追加这段约定，保留原有规则；重复点击不会再添加相同内容。只有你主动点击才会写入规则文件。

新对话仍应使用同一项目目录；AI 是否按约定汇报，要以接入页的最近接收时间和实际任务为准。旧版本没有“项目接入”页面时，可使用随文提供的 [AI 进度汇报说明](seqivo-progress-prompt.zh-CN.md) 手动接入。

### 第一次如何确认接入成功

“项目接入”显示“已收到汇报”和最近接收时间，点击“查看对应任务”可直接核对内容；AI 读取到 `status: "accepted"` 的回执；`tasks.json` 中出现同一任务。这三个结果能确认这条记录已经进入序程。只看到 inbox 里多了一个文件，还不能确定接入成功。

## 5 本次演示怎样更新看板

演示项目有三项工作：“统计文件类型”“增加整理预演”“处理同名文件”。助手按实际文件协议写入三条创建事件，再把第一项更新为进行中；后台接收后，界面自动显示 **3 项任务、2 项未开始、1 项进行中**。

![进度文件被接收后显示的项目统计](assets/onboarding/progress-running.png)

随后在隔离目录里实现了一个文件名统计函数，运行两项自动测试：普通扩展名分组、无扩展名分组。两项均通过。助手再写入结果和测试记录引用，任务进入“待验收”。另外两项仍未开始。

![任务详情展示目标 已完成的部分和下一步](assets/onboarding/task-result.png)

这次实际演示经过了“写文件 → 接收回执 → 更新快照 → 更新界面”，没有调用真实 Codex／Claude 执行插件，也没有连接业务后台。小函数的测试只证明统计功能，不代表移动文件、覆盖处理或整个应用已经完成。

### 看懂状态和百分比

| 界面内容 | 表示什么 |
| --- | --- |
| 未开始／进行中 | 工作还未开始，或 AI 汇报正在推进。 |
| 遇到阻碍 | 有明确原因需要处理；看“下一步”或“需要我处理”。 |
| 待验收 | AI 已提交结果，轮到你核对。 |
| 已完成 | 当前结果已提交，并通过人工验收。 |
| 待验证／已验证 | 独立的测试记录状态；一段“测试通过”的汇报不会自动改变它。 |
| 任务验收进度 | 当前已通过的验收条目占比，不是按代码行数估算的开发进度。 |
| 项目验收完成率 | 已通过验收的任务数 ÷ 当前有效任务数。 |

因此，演示里的统计功能虽然有两项测试记录，人工尚未验收时完成率仍是 0%。这正是在区分“AI 说做完了”和“你确认满足要求了”。

## 6 核对证据和继续下一段对话

在“任务清单”点开任务，先看“原本要什么”“现在做到哪”“怎么实现”，再展开“证据与来源”。证据引用可以是测试报告、文件路径或产物链接；序程保存引用，不会自动判断文件内容能否证明整个功能完成。

![展开证据并找到人工验收入口](assets/onboarding/evidence.png)

打开实际产物或报告，逐条核对要求后，再点“人工验收”。本例的证据是 `reports/count-files-test.txt`。如果发现缺功能，选“未通过”并写清问题。单独点击验证待办的圆圈，只是在维护该条待办，不等于整项任务验收通过。

新开 Codex／Claude 对话时，仍选择同一个项目目录；可沿用已添加的项目规则，或再次让 AI 阅读 `.taskboard/REPORTING.md`、`.taskboard/CONTEXT.md` 和 `.taskboard/tasks.json`。这些文件用于恢复项目目标、任务进度、已有证据和下一步，不包含所有旧聊天原文。

文件接入本身不授予“继续运行 AI”的权限。如果还想在序程中点“让 AI 开始”“继续任务”或“暂停”，需要另行配置“接入与插件”，绑定执行会话并启用相应执行工具。**只想看进度时，可以先不配置执行插件、自动续跑、SSH 或 tmux。**

## 7 手机如何看到这台电脑的进度

本地文件接入跑通后，再按需开启手机连接。这里需要已有的序程 HTTPS 服务地址和账号；前面的 `pnpm server` 只启动本机服务，不会自动部署手机可访问的服务器。

1. 在电脑的“更多功能 → 手机连接”填写你自己的 HTTPS 服务地址，登录账号，选择允许同步的项目。
2. 手机浏览器打开同一个服务地址，登录同一账号，查看已同步的任务；不必先安装手机 App。
3. 电脑负责读取本地项目并同步。电脑离线时，手机只能看到最后一次已同步的记录；远程让电脑继续工作也需要电脑在线、相关执行工具已配置。

手机不会直接读取电脑硬盘，也不能把手机上的 `127.0.0.1` 当成电脑地址。本地接入与远程同步是两步，先完成本地接入即可。私用服务地址、访问令牌、密码和私钥不应写进要提交 GitHub 的说明或项目记录。

具体账号步骤见仓库 `docs/account-setup.md`；无需为了手机看进度，把项目开发成一个带业务 API 的网站。

## 8 没看到进度时先检查这些

| 现象 | 先做什么 |
| --- | --- |
| AI 聊天里说完成了，看板没变化 | 让 AI 检查是否写入 inbox，并读取对应回执。 |
| 项目里没有 .taskboard | 核对已绑定的目录、应用是否运行、目录是否允许写入。 |
| Mac 一直显示“正在准备汇报说明” | 查看系统是否正询问“序程”访问文稿或桌面文件夹；项目位于其中时，允许对应文件夹访问，无需开启完全磁盘访问。 |
| inbox 有文件但没收到回执 | 确认序程后台运行；事件文件应以 .json 结尾，单个文件不超过 1 MB；不要放进多层子目录。 |
| 接入页显示“汇报未接收” | 把具体原因交给 AI 修正；任务修订冲突要先重新读取 tasks.json，不能盲目重试旧内容。 |
| 修改 tasks.json 后界面没更新 | 它是生成的快照，应通过 inbox 提交事件；不要直接修改快照或数据库。 |
| 点“导入”提示找不到文件 | 普通代码目录走“新建”；导入只读专用 project.json。 |
| 能看进度但“继续任务”不可用 | 文件汇报和 AI 执行是两种接入；后者还需要执行插件和会话绑定。 |
| 手机没出现新进度 | 先检查电脑本地是否更新，再检查手机连接与项目同步范围。 |

### 安装包与当前源码

v0.4.1 包含“选择项目 → 复制提示词 → 查看真实汇报”及可选项目规则接入。当前公开发布内容见 [公开发行记录](public-release-status.json)；早期开发记录保留在 `docs/current-delivery-status.json`。本地接入不需要更新远程服务器；三系统原生验收和真实 Claude 执行仍未全部完成。

### 本次核对范围

本机隔离演示成功接收 6 条文件事件：3 条创建、2 条进度更新、1 条证据；任务快照与页面一致，小函数自动测试 2／2 通过。本版文件桥与核心定向测试 30／30 通过。没有测试新电脑完整安装、真实 Claude 执行或本次手机同步，也没有改变正式项目的验收状态。

本次接入界面进一步验证了真实事件接收、旧修订拒绝、错误提示和复制入口；对应结果见 [项目接入测试记录](local-reporting-results.json)。

依据为当前 `server/files.mjs`、`server/file-bridge-worker.mjs`、`server/store.mjs`、`src/App.tsx`、`src/SupervisionPanel.tsx` 与 `docs/current-delivery-status.json`。进一步参考 [现有使用说明](getting-started.md)、[桌面构建说明](desktop-build.md)、[账号接入说明](account-setup.md)。

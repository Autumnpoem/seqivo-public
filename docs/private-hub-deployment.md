# 私用 Hub 公网部署验证

2026-09-26，Seqivo 0.2.3 已部署到用户自己的 Ubuntu 22.04 服务器。没有域名，使用 Let's Encrypt 公网 IP 证书与 nginx；Node 24 Hub 仅监听回环地址。服务器地址和设备凭据保存在用户本机私密配置，不写入仓库或通用应用默认值。

## 已完成的实际验证

- 公网 HTTPS 证书受信任，HTTP 跳转到 HTTPS，匿名 API 返回 401。正式证书续期演练及 nginx 重载成功，续期定时器每日检查两次。
- 桌面保存个人服务器地址，主动同步一个真实项目与 24 项任务。服务器重启 Hub 服务后，任务完整保留，桌面自动恢复连接。
- Chrome 和 WebKit 以手机尺寸访问真实公网服务：一次性配对、浅色/深色界面、刷新后会话、只读权限和撤销通过。Chrome 提交的任务更新经过公网 Hub 队列写入桌面 SQLite，网页收到确认回执，后续投影与桌面版本一致。
- 每日备份服务实际执行成功。隔离恢复验证了 24 项任务、管理员身份、项目电脑授权和设备撤销；另一个测试租户无法读取恢复的项目。已在本机另存一份受保护的恢复副本。
- 网页生产构建与 16 项 Hub/备份测试通过；部署配置经过独立审查。
- 后续安全复查补齐了原先未启用的主机防火墙：UFW 已开启并持久化，IPv4/IPv6 默认拒绝入站，只为 SSH、证书验证和 HTTPS 配置 TCP 规则，SSH 限速。启用后新 SSH 连接、加密通信、设备权限和桌面同步均通过；详见[安全检查摘要](private-hub-security-results.json)。

重启后立即备份曾因 WAL/SHM 文件缺失而失败。备份服务已允许原服务用户在数据目录创建 SQLite 协调文件，数据库仍以只读连接打开；真实 systemd 沙箱中的冷启动用例、正式备份及隔离恢复均通过。

## 尚需验证的范围

实体手机与蜂窝网络访问需用户实测；真实 AI 的跨网络继续、暂停和断线恢复仍需单独验证。手机尺寸浏览器、远程文字更新与命令回执不等同于这些场景通过。手机端目前是网页/PWA，没有原生 App。

已验证的是服务开机启用配置和 Hub 服务重启，未执行整台服务器重启。证书续期演练通过，尚未观察自然到期周期。每日备份当前保存在服务器本机，自动异地上传和自动清理尚未配置。

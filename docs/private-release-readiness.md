# Private GitHub source readiness audit

Historical audit. The private repository has since received source updates. Current delivery status is tracked in the [remaining-work plan](remaining-work-plan.md); inspect the exact staged set before every sync. Cloud CI remains disabled by user choice. This document's original observations and counts are not a fresh release audit.

Scope: the current workspace before its first private GitHub source push. This is a source and packaging inventory, not approval for public distribution. The first audit preceded Git initialization; the repository now exists, but the final staged set and GitHub Actions run require separate inspection. The audit did not read credential values or modify upstream license text.

## Block before the first source push

1. **Keep live taskboard project data out of source history.** The original audit found `.taskboard/project.json`, about 20 KB with 23 task entries and project/validation fields, outside the former ignore rules. [`.gitignore`](../.gitignore) now excludes `.taskboard/` as a whole. Check the actual staged set; a force-added file or earlier index entry would override the intended boundary.
2. **Keep raw QA evidence local.** The original audit found real Codex/workflow JSON, Codex probe JSONL, upgrade records, native process records, screenshots, and build/test logs under `design/qa/`; several logs contain absolute home paths. [`.gitignore`](../.gitignore) now excludes that directory. A reviewed, redacted summary may be included deliberately, but the raw directory should not be staged. The release test matrix currently links to this local evidence and `.taskboard/project.json`; those links will not work in the private source repository unless a safe evidence subset is deliberately included or the links are relabelled local-only.
3. **Inspect the exact first staged set.** Before any push, inspect the complete staged paths, including hidden files, then perform a content scan that prints only filenames and match categories. Verify that `.taskboard/`, `design/qa/`, `.pnpm-store/`, `.runtime/`, generated `release/`, `dist/`, `src-tauri/target/`, `src-tauri/binaries/`, and `src-tauri/resources/` are absent. The new ignore rules cover `.pnpm-store/` as well. No `access.json`, `remote-link.json`, `connection.json`, private key, or provider key shape was found among the bounded source scan; absence in that scan is not a substitute for inspecting the eventual Git index.

## Private-repository, non-blocking findings

- [`.github/workflows/desktop.yml`](../.github/workflows/desktop.yml) runs on every push, pull request, and manual dispatch. It tests, builds on macOS/Windows/Ubuntu, then uploads generated installers as **private repository artifacts**. It has no GitHub Release or public deployment step. The matrix has not run in GitHub yet, so cross-platform success is unverified. `macos-latest`, `windows-latest`, the stable Rust toolchain, and major-version action tags can change between runs; pinning exact runner/tool/action revisions and publishing checksums would improve reproducibility before relying on artifacts for a release. No production signing or notarization is configured in this workflow, which is acceptable for source storage but must be addressed for a public installer release.
- [`scripts/prepare-desktop.mjs`](../scripts/prepare-desktop.mjs) copies `server/`, `plugins/`, and `dist/` recursively into the app resources. It filters Python bytecode but otherwise packages any extra file placed under those source directories. Audit those directories before packaging and avoid keeping local credentials there. The generated `runtime.json` currently records an absolute local `licenseSource` path, which reveals a build-host path in a locally built app. Store a source category or official URL instead before external distribution.
- [`plugins/codex-autocontinue/PROVENANCE.md`](../plugins/codex-autocontinue/PROVENANCE.md) identifies vendored code from the user's [`Autumnpoem/codex-autocontinue`](https://github.com/Autumnpoem/codex-autocontinue) repository and a specific commit. The bundled [`vendor/LICENSE`](../plugins/codex-autocontinue/vendor/LICENSE) still contains unresolved Git conflict markers in its copyright line. The upstream repository describes itself as MIT licensed, but the current local license text does not resolve which attribution line is intended. `desktop:prepare` checks only that this file exists, and the desktop bundle includes it. Do not silently choose an attribution or change upstream terms in this project; resolve and record the authoritative text with the upstream owner before distributing installers outside the private workspace.

## Verification and handoff

Subsequent scoped evidence (2026-10-18): APP403 exercised the ordinary v7 Android APK in an API 35 emulator against an isolated Hub using the PACKAGE401 packaged backend resources. It completed login, preview, draft feedback and one explicit linked-task confirmation, while the original task remained `unverified`. The user-visible build receipt was `ready`. Its accompanying generic job-layer `resultUnknown=true` field is retained verbatim; that field means the layer does not assert the command's business result, not that retirement or process identity is unknown, and it does not by itself negate the independent ready receipt. A separate Documents-root attempt failed as `BUILD_EXECUTOR_UNKNOWN` and was not retried; the cause remains unknown. This limited emulator flow is not physical-phone, real-AI, latest native Mac UI, formal-signing or release acceptance; see the [controlled-preview result](controlled-preview-build-test-results.json). This does not update the historical audit findings above.

PACKAGE418 later built an isolated ad-hoc signed desktop candidate from a fixed source snapshot and explicit overlays. Its packaged resource probes, controlled-build live case and packaged desktop-transport test passed. Separately, FIX414 source regressions for transport, prior preview access and HTTP authorization passed; UI417 source mock checks passed as well. The native bridge now uses the confirmed current loopback port; the web route is unchanged, the iframe sandbox remains opaque, and failure to read the port prevents issuance. The Mac was locked during both native UI attempts, so no native GUI result is claimed; the package was not notarized, deployed, or tested on a physical phone. See the [controlled-preview result](controlled-preview-build-test-results.json); this remains a scoped development result, not a refreshed release audit.

Read-only checks covered `.gitignore`, the workflow, the desktop preparation script, Tauri bundle configuration, vendored provenance/license, filename inventory, QA JSON shapes, and a bounded key-pattern scan that emitted only paths/categories. The local release ZIPs (about 85 MB total), generated Tauri target (about 2.1 GB), raw QA evidence (about 1.7 MB), and live `.taskboard/` records are now covered by `.gitignore`. `package.json` marks the npm package private. The first private GitHub push should proceed only after a staged-file review; CI/build status should be reported as unverified until a real run completes. The independent verification-state findings are documented in the local `design/qa/release-readiness/verification-review.md` and should be resolved before treating a test badge as authoritative.

If a mistakenly staged file has **not** been pushed, remove it from the index and recheck the staged set. If task or credential data has reached GitHub, first stop further sharing, remove it from repository history through a reviewed remediation, and rotate any affected credential through its provider. Do not delete the local taskboard database as a substitute for repository cleanup.

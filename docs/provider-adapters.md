# Claude Code and Cursor Agent adapters

Both adapters are optional local plugins and start disabled. They use the existing plugin v1 lifecycle and own storage under their assigned `dataDir`; neither changes a provider login, endpoint, global model, or project settings. Configure an installed executable path and enable the chosen plugin before creating a task session. A task must have an explicit project directory. The adapter records its canonical path and its own session ID, then rejects a later directory change or a manually bound foreign conversation ID. `createSession` never sends a model prompt: Claude Code registers a UUID for its first `--session-id` run; Cursor authenticates over ACP and calls `session/new` without `session/prompt`.

| Provider | Turn protocol | Start confirmation | Successful terminal proof |
| --- | --- | --- | --- |
| Claude Code | `claude -p ... --output-format stream-json --verbose --session-id UUID`, then `--resume UUID` | `system/init` with matching session ID | `result` without error/permission denials **and** process exit 0 |
| Cursor Agent | `agent [--model MODEL] acp`, JSON-RPC `initialize`, `authenticate` (`cursor_login`), `session/load`, `session/prompt` | Matching `session/update` agent text/thought/tool notification | `session/prompt` response `stopReason="end_turn"` |

Only a confirmed start changes the task to `running`. A successful terminal outcome changes it to `submitted`, still awaiting human acceptance. The adapter checks that the session, canonical directory and task content version still match before terminal status updates. Authentication failures and permission requests become blocked. Cursor permission requests receive `reject-once`; questions and plan approvals are declined. Claude uses `dontAsk`, never bypass permissions. The app does not log in to either provider. Real provider compatibility remains unverified until the user installs and authenticates the CLIs.

Each `resume` may include `instructions`, `model`, `role`, `workspace`, `reviewOf`, and `evidenceOnly` for that one command. The command ID binds those values in the durable digest; reusing the ID with a different payload fails. A supplied workspace must resolve to the session's canonical project directory. Claude passes a per-turn `--model`; Cursor passes `--model` only to that ACP process. An evidence-only Claude turn restricts built-in tools to `Read,Grep,Glob` and denies MCP tools. Cursor requests ACP `ask` mode through `session/set_mode` before any prompt; if the server does not confirm it, the adapter returns `not_started` and sends no prompt. These modes limit the adapter's own tool grants; locally configured provider hooks or other external integrations are outside this plugin's control.

The command journal is written before any prompt send. Immediately before Claude process launch or Cursor `session/prompt`, the adapter calls its optional trusted `authorizeExecution({taskId,commandId})` context callback to validate the current execution lease. A denial returns `not_started` without sending. After a crash, `sending`, `starting`, `running`, and `pausing` become `unknown`; the adapter never retries them automatically. `getExecution({taskId,commandId})` exposes `not_started` for a missing command and `running`, `completed`, `failed`, `paused`, or `unknown` for owned commands. An `unknown` command can be unlocked only by explicit `reconcile({taskId,expectedRevision,confirmStopped:true})` after the user confirms the provider process stopped. Reconcile never sends a prompt. Pause only acts on the adapter's live owned process/session and reports `paused` only after a confirmed interrupt/cancel; ambiguous termination stays `unknown`. A pause during the pre-send lease check prevents the prompt. `close()` stops live children and throws when shutdown cannot be confirmed.

Configuration fields are `executablePath`, optional `model`, and `maxDurationSeconds` (10–14400). Claude additionally supports `maxBudgetUsd` for a single `-p` invocation; the configured value is applied per turn, and a per-turn model override never rewrites it. Cursor ACP does not expose a documented per-request budget cap, so that field is not offered there. No provider executable is downloaded or invoked by the adapter tests; [the tests](../tests/provider-adapters.test.mjs) spawn only generated fake CLI/ACP scripts.

Protocol references: [Claude headless](https://code.claude.com/docs/en/headless), [Claude CLI reference](https://code.claude.com/docs/en/cli-reference), and [Cursor ACP](https://cursor.com/docs/cli/acp).

## 先看这版要交付什么

优先完成 **Android App + Mac 执行端的完整流程**：登录 → 查看待办 → 新建或继续 AI 对话 → 暂停并接管 → 使用 tmux → 交还 AI → 查看证据并验收。iPhone 继续使用网页；Ubuntu、Windows 和其他扩展按后续批次完成。

已有账号、配对、任务、证据、人工验收、收件箱和跨对话交接继续使用。Shell 的真实命令输入输出，以及 tmux 列表、新建、默认选择和切换已有实现及局部测试。剩余重点是修复退出和交还问题、补恢复与权限检查、完成同一版本的 App 联调和安装包验收，不能把局部通过写成所有平台已适配。

**Shell 和 tmux 分别交付：**Shell 负责真实输入、输出、快捷键和交互程序；tmux 负责列出正在运行的会话、默认进入、手动切换和保留现场。两者都要从最终 App 入口验证。这里采用类似 Termius 的连接与会话操作体验；本轮不包含 SFTP、完整桌面远控或电脑重启后自动复活程序。

## tmux 必须遵守的交互约定

1. **主动连接直接打开默认会话。** 第一次没有默认时，选择已有会话或明确新建。
2. **底部显示 `会话：开发主线 ▾`。** 点开列出有权访问的真实运行会话，能看到当前会话和默认标记。
3. **临时切换不修改默认。** “设为默认”是独立操作；在 A、B 间切换不结束其中的程序。
4. **掉线恢复与重新连接分开。** 短暂断网、切后台后接回原来的当前会话；主动断开后新连接进入默认。未确认输入不自动重发。
5. **默认失效就明确选择。** 会话结束、同名重建或身份变化时提示重新选择，不偷偷创建或连接替代会话。

首次授权、新设备和授权失效有明确确认；后续有效连接复用账号与设备绑定。电脑需开机联网。现有普通 AI 对话不会因为增加 tmux 而自动变成 tmux 内的程序。

## 2. 固定的用户体验

1. 电脑端首次启用终端功能，选择普通系统账号对应的终端配置，并授权指定设备。手机沿用现有账号；看板查看权限不会自动获得终端权限。
2. 手机点“终端”，顶部始终显示电脑、项目和查看/控制状态。第一次没有默认会话时，选择已有会话，或明确新建并设为默认。
3. 以后主动新连接直接进入默认会话。底部固定 `会话：开发主线 ▾`，展开可滚动抽屉，显示真实会话名、当前标记和默认星标。
4. 点另一个会话只切换当前画面；“设为默认”是单独操作，同账号、同电脑及同终端配置共享偏好。
5. 手机暂时断网、切后台或锁屏后恢复同一次连接，接回此前正在查看的会话；主动断开再连接则进入默认。恢复须重新校验身份和授权，输入不自动补发。
6. 默认会话结束、身份变化或被撤销时，提示重新选择，不随机附着、不偷偷创建同名替代会话；用户可选存活会话或明确新建，再单独设为默认，下次主动连接须命中该会话身份。
7. 底部另有 Ctrl、Esc、Tab、方向键和中断入口；软键盘弹出后仍能切换会话。支持浅色/深色、大字号、复制与明确确认的多行粘贴。

已有 tmux 中的程序保留原现场；应用内普通 AI 聊天不会自动迁移进 tmux。详细默认/重连规则以[会话交互约定](remote-terminal-sessions.md)为准。

当前只读查看和明确授权后操作已有 tmux 均有本地实现；**P1-TMUX-EXISTING** 还需完成最新 Hub/界面和手机联调。只读连接不能输入、新建或接管；受管项目的可写连接须通过执行协调，授权扩展必须明确选择。不能通过杀掉原程序完成接管，也不能把当前目录检查说成系统文件隔离；同一会话的其他 tmux 客户端仍可能输入。

## 4. 技术拆分与插件边界

建议通路为：**手机终端页面 ↔ HTTPS/WSS Hub 中继 ↔ 电脑主动建立的连接 ↔ 本地终端插件 ↔ PTY/tmux**。Hub 负责身份与路由，终端运行在用户电脑；电脑不开放公网 SSH 端口，现有防火墙保持开启。

| 模块 | 实现落点（部分已接线，完整验收未完成） | 责任 |
| --- | --- | --- |
| 终端界面 | `src/TerminalPanel.tsx`、终端客户端模块 | 本地打包的 xterm.js、状态条、会话抽屉、软键盘辅助、输出恢复 |
| 核心终端协调 | `server/terminal/`、现有 core/执行租约扩展 | 可信 PTY 管理器、授权、目标绑定、输入门禁、控制权代次、进程身份、接管状态与恢复记录 |
| 内置终端扩展 | `plugins/local-terminal/plugin.json`、`server/terminal/plugin-lifecycle.mjs`；适配器在 `server/terminal/` | 已有 Core-owned 能力注册、owner 管理及启停门控；补齐跨重启未知状态恢复、升级与回滚。所有远程输入经核心管理器；不视为第三方插件市场或完整跨平台插件验收 |
| Hub 实时中继 | `server/hub/terminal-*`、节点连接模块 | 一次性连接票据、账号/设备/节点绑定、撤销广播、流量及连接限制 |
| 数据 | 核心/Hub 的增量 metadata 与迁移 | 终端配置、授权、默认偏好、活动连接和接管记录；保留旧任务和证据 |
| 测试与打包 | `tests/terminal-*`、`tests/e2e/terminal-*`、桌面打包脚本 | 原生依赖兼容、协议/生命周期、浏览器与真机记录 |

现有插件接口面向离散调用，不能直接用高频按键塞进任务命令队列。新增终端能力及有界流通道，旧插件 API 保持兼容；核心负责授权，远程插件接口不得绕过管理器或扩大权限。内置可信适配器可以放在隔离崩溃的子进程中，但插件本身不是系统安全沙箱，第一版不向任意第三方插件开放终端运行权限。插件退出必须先撤销入口并确认自有附着进程退出，不能杀掉用户既有 tmux server。应补充插件“附着客户端”和“用户会话”的不同归属规则。

当前 PTY 使用 `node-pty`，已接入 Mac 资源准备和构建；继续验证最终安装包内与打包 Node 的兼容性。目标平台与发行架构仍需本项目分别实测。[node-pty 官方说明](https://github.com/microsoft/node-pty)

终端前端已使用 xterm.js，组件随应用打包；访问控制由核心与 Hub 实施，不能直接把示例 WebSocket 服务用于生产。[xterm.js 安全指南](https://xtermjs.org/docs/guides/security/)

## 5. 必须先定清的状态与安全规则

**身份和权限。** 每次终端连接绑定账号、设备、目标电脑、终端配置及允许的操作。分别定义查看、输入、创建会话和接管能力；权限变更检查覆盖已经打开的连接。首次授权、新设备及授权失效需要明确确认；日常连接使用短期凭据自动续接，不重复填写 SSH 信息。WebSocket 升级/首帧须认证并检查 Origin，短期票据一次使用，凭据不放 URL 或日志。终端输入不得进入现有离线任务队列。

**输入与输出。** 控制权代次、连接 ID、会话身份和输入序号共同防止旧连接继续写入。切换先停输入，目标确认后再恢复；确认前的按键不送给任何会话。连接丢失时立即禁止新输入，不持久化待发送按键、不自动重放；“字节已写入 PTY”不等于“命令执行成功”。不确定时展示现场供用户核对，不宣称 Shell 命令具有严格 exactly-once 语义。

输出按字节序号保留有界缓冲，重连恢复缓冲内的缺失部分；超出缓冲时明确提示缺口。tmux 可重新同步当前终端画面；普通 Shell 只能说明历史输出不完整，并经用户确认后继续当前进程，不能把截断的 ANSI 流直接拼成完整历史。连接数、帧长、缓冲和输出速率必须有上限；慢手机不能拖垮任务核心。具体限额在 C/F 的容量测试中固定并写入报告。

**tmux 身份。** 目标由电脑、终端配置、server 实例和 session ID 识别；名称只供显示。server 重启或会话删除后，复用 ID/同名会话不能自动冒充原目标。使用参数数组与结构化输出，避免把名称拼进命令。会话切换只影响当前客户端，不能强制踢掉本机或其他手机。[tmux 官方手册](https://man.openbsd.org/tmux)

**进程生命周期。** 手机断线或普通“断开连接”只结束附着，不结束 tmux 内的程序；“终止程序/结束会话”单独呈现。相关进程仍可能写入工作区、仍有未受控输入入口或归属无法证明时，不能释放相应写入控制权。保留空闲会话交还已有本机输入冻结/停驻机制，真实 AI 和 App 仍待验证；不能凭 shell 名称、空闲显示或 detach 放行。Mac 正常退出、异常退出、电脑休眠、Hub 重启分别测试；应用重开先对账，未知状态继续阻止 AI 自动续跑。电脑重启后不承诺恢复原进程。

普通 Shell 与 tmux 分别验收：Shell 原进程退出时明确显示结束；缓冲缺口须说明并由用户确认继续，不能冒充完整历史。tmux 短暂恢复接回当前会话，必要时重新同步画面；主动新连接进入默认，保持原会话及程序。两者均重新核验权限、不补发输入。已有 tmux 另核验外部结束、同名替换和撤权，不用受管会话的结果替代。

**人工接管。** 建议状态为 AI 控制 → 停止中 → 人工控制 → 交还检查 → AI 可继续；任一阶段事实不明则进入“需要处理”。先禁止新的 AI 调度，再请求停止，并核对受管执行进程及相关写入子进程；暂停响应、锁到期和 tmux detach 都不能证明停止。无法证明时不得开放同工作区的写入接管。对既有、未受管 tmux 会话可提供独立终端访问，但不能因此声称建立了安全接管关系。

交还时先封住本次人工输入，再核对仍运行的进程、工作目录、文件差异和用户填写的待解决问题。当前 Git 快照包含已跟踪和未忽略的未跟踪文件，忽略文件不在范围内；界面与 AI 摘要须显示该范围。明确处理可能仍写入的后台进程后，再交回控制权；将现场摘要交给 AI，要求重新读取受影响文件，不能仅靠旧聊天继续改。进程核验是当时可见的工作目录与写句柄证据，应用之外的本地客户端或编辑器不受应用锁强制约束；检测到争用或无法确认时应提示并保持阻塞，不伪称操作系统级独占。

**权限范围与保密。** 默认普通系统账号；项目目录只是打开位置，不能充当系统沙箱。日志默认只记录谁连接/切换/撤销及结果，不记录按键、密码或完整终端输出；输出不自动成为共享任务证据。终端控制序列、标题与链接作为不可信数据处理，未经用户动作不得写剪贴板或执行额外操作。当前范围是传输加密与严格访问控制；Hub 属于可信服务，不宣称端到端加密或服务器管理员不可见。

## 6. 最低验收矩阵

| 场景 | 自动化检查 | 真实操作与通过条件 |
| --- | --- | --- |
| 真终端 | PTY 生命周期、尺寸、编码、交互程序 | Mac 中使用命令、补全、Ctrl-C 和交互式 CLI，响应对应真实进程 |
| 核验拒绝后停止输入 | APP207 客户端定向结果已通过；实际 App 故障组合待验 | 进程证明或执行权核验失败后停止后续输入；迟到回执不能放行；重新连接后重新核验，不补发旧输入 |
| 默认与切换 | 列表/身份、偏好持久化、删除竞态 | 默认 A → 切 B → 主动重连 A；设置 B 默认后另一设备新连接 B，原程序不重启 |
| 断网与恢复 | 输出偏移、旧代次拒绝、输入确认丢失 | Wi-Fi/蜂窝切换、后台与锁屏后回到当前会话；不补发按键或命令 |
| 授权与撤销 | 跨账号/设备/节点、票据复用、错误 Origin、旧连接继续发包 | 撤销后已连接手机不能继续读取或输入，服务端有拒绝记录 |
| 接管 | AI 停止延迟、子进程残留、崩溃与并发请求 | 实际受管写入停止后才允许人工接管；事实不明显示待处理 |
| 交还 | 输入门禁、文件差异和后台进程检查 | 人工修改后交还，AI 读到新内容并完成下一步，原验收记录不被改写 |
| 大输出与异常 | 有界缓冲、慢消费者、插件崩溃、同名/复用会话 ID | 主界面和任务同步仍可用；输出缺口明确，不显示伪完整历史 |
| 手机界面 | Chromium/WebKit 窄屏、滚动、键盘和长列表 | iPhone Safari、Android Chrome 亲手操作中文输入、大字号、复制/多行粘贴及底部切换 |
| 升级/回滚 | 数据副本、配置兼容、受影响原功能回归 | Mac 正常退出再打开、tmux/连接对账；任务、证据、原人工验收保持 |

每条记录版本、环境、操作、预期、实际、证据和限制；浏览器视口不记成实体手机，Windows 编译不记成 Windows 实测。模拟提供方用于协议故障测试，真实 Codex 的可丢弃项目用于最终接管演示。独立安全复审与实现者的自测分别记录。

新增能力保持“待实现/未验证”直到有代码及相应证据。细分待办可以完成，整项仍须满足所有标准；用户人工验收单独保存，不由测试计数替代。

## 7. 演示脚本与交付物

最终演示在可丢弃项目中进行：电脑让 Codex 修改一个文件 → 手机查看任务 → 请求接管并确认实际停止 → 自动进入默认 tmux 会话 → 底部切到另一会话再切回 → 运行测试并修改文件 → 断网/恢复仍在原现场且无重放 → 交还 AI 并读取新现场 → AI 完成后呈现当版证据 → 用户验收。

每一批交付实现及必要迁移、可重现测试、已验证/剩余清单、简洁使用说明。G 另交付 Mac 安装包、私用 Hub 的备份/升级/回滚步骤和完整演示证据；H 按平台单独交付。仓库保持私有，服务器地址、凭据和原始私有输出不进入 GitHub，云端 CI 保持用户指定的暂停状态。

## 8. Windows、Ubuntu 与后续清单

Windows 配置须显示当前是 Windows 还是 WSL、发行版和路径归属，分别校验权限与工作目录；不同发行版的会话和默认偏好隔离。没有 WSL 时普通 Shell 可单独使用，tmux 能力显示未配置，不伪装可用。安装 WSL 所需系统操作到对应阶段再处理。

## 9. 用户配合与计划调整

当前编写计划不需要额外配置。实施过程中可以自动完成代码、隔离测试、构建和证据整理；首次终端设备授权、系统权限提示和锁屏密码由用户在设备上完成。真机断网使镜像不可控、或需要实际触屏评价时，提供一次一组的简短操作步骤。Windows/Ubuntu 阶段需要可用的目标系统或用户提供受控测试环境，缺失时对应结果保持未验证。

依赖不兼容先做小范围替代验证再更新方案；不能用静态演示代替真实 PTY，也不能为交付速度跳过进程停止或访问控制。旧 P0 验收结论的冲突先对照证据说明，任何发布条件的放宽须明确记录依据，不把本计划当成用户已经验收全部功能。
